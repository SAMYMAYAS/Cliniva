## Application et chaîne d’exécution

- Application de clinique Windows : Python + FastAPI, Uvicorn en arrière-plan, pywebview pour la fenêtre de bureau, PostgreSQL via psycopg2/pool partagé.
- UI HTML/Jinja + Tailwind + JavaScript (pas de framework SPA repéré). templates/dashboard.html est l’enveloppe/navigation; il charge /api/modules/{nom}, injecte le fragment HTML et réexécute les scripts inline. Chaque modules/*.py combine généralement manager/SQL, routes FastAPI, render_html(), HTML et JS.
- Chaîne fonctionnelle à préserver : geste UI → fetch JS → route API → authentification/permission/validation → manager/SQL et éventuellement fichier uploads → JSON/réponse HTML/PDF → tableau/modal/document. Suivre les consommateurs avals avant toute modification d’un champ.
- main.py : construction FastAPI, routeurs, login/session, chargeur modules et lanceur Uvicorn/pywebview. app/auth.py : session, hash, audit. database.py : pool PostgreSQL, init/DDL, chemins uploads. Les migrations sont dispersées dans init_database() et les modules, sans outil versionné identifié.

## Fonctionnel existant à ne pas perdre

- Passages : tableau remodelé mais informations conservées; filtres en modal (dont date de naissance), recherche DOB, deux styles (tableau et lignes arrondies, fond blanc), statut consultation, Actions en dernier dropdown; scans multiples visibles en lightbox intégrée avec navigation/zoom/rotation/impression; PDF demande visible dans le logiciel.
- DME : ouverture depuis passage corrigée après une erreur de syntaxe d’un script injecté. Choix lecture seule ou exécution; exécution met passage En cours; enregistrement verrouille la consultation et met Terminé. Historiques/archives lisibles, champs cliniques, ordonnances, CR/livrets consultables. Demande examen et scans accessibles même en lecture seule; observations/renseignements cliniques n’affichent que les cases Oui cochées. L’application s’ouvre par défaut sur Accueil/Passages après login.
- Ordonnances : formulaire ajout rapide médicament depuis DME, catalogue recherché/sélectionné automatiquement après ajout; lecture seule protégée. Chaque ordonnance est filtrée/enregistrée par id_patient + id_passage + id_consultation. Livret permet de choisir couverture dans uploads/model_templates/Page_De_Garde.
- Caisse : mouvements nommés encaissement total, partiel, encaissement du reste; reçu du reste doit montrer le montant de la régularisation, et journal/PV utilisent les libellés adaptés. KPI remboursements_total sur période filtrée et colonne Nature des prestations ajoutés au PV. Remboursement débite la caisse et garde motif.
- Permissions caisse : cases encaissement, reste, remise, journal et nouvelle permission indépendante cash_refund. Route annulation vérifie cash_refund côté serveur, interface/actions la respectent. Comptes historiques sans clé cash_refund héritent temporairement de cash_remise; ouvrir/modifier/sauvegarder le compte persiste le droit dédié. Presets Caissier, Direction et Administrateur incluent le remboursement.
- Passage remboursé : cellule règlement affiche Remboursé, montant et cause raison_annulation.
- Correction complète depuis le tableau : l’action sous `pat_edit` ouvre le même formulaire de passage que « Nouveau Passage », prérempli avec le patient, le médecin, les actes, les informations médicales, les scans, la date et l’heure. Les champs personnels (nom, prénom, naissance, genre, groupe sanguin, téléphones, e-mail, wilaya, commune) sont modifiables directement dans ce formulaire; le bouton patient ouvre également la fiche habituelle préremplie pour les photos. Les corrections sont envoyées ensemble à une API qui vérifie et verrouille le passage, refuse toute avance ou mouvement de caisse, tout dossier DME et tout statut autre que `En attente`; ces règles sont revalidées à l’enregistrement. Les valeurs financières restent protégées; si les actes changent avant encaissement, le total et le reste sont recalculés côté serveur en conservant la remise. Les données biométriques sont chargées seulement à l’ouverture du formulaire d’édition. Après sauvegarde, la liste est rafraîchie et la demande d’examen réouverte depuis les informations mises à jour.
- Suppression magique de passage/paiement/DME réservée à l’administrateur SYSTEM, confirmations et mot de passe; suppression destructive, confirmer la portée avant toute évolution.
- Logo Cliniva SVG inline vert/noir dans le menu et l’écran connexion.
